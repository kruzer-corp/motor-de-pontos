Dois mundos distintos nesta jornada

O Arquiteto não usa esta interface. Ele especifica produtos, acumula pontos e resgata pelo seu canal próprio (loja, app ou dispositivo). O painel administrativo é usado pelo Admin e pelo Analista/Operador para consultar as transações do arquiteto, gerenciar o programa e aprovar resgates.

🏗️ Arquiteto = age no canal próprio (loja/app/dispositivo)
📊 Admin / Analista = consulta e gerencia no painel
Canal de interação:
Borda tracejada = ação no canal próprio do arquiteto (fora deste painel)
Borda sólida roxa = ação no painel administrativo
Borda sólida azul = ação no painel administrativo (Admin)

Job to Be Done — Consulta Quando preciso acompanhar o volume de especificações, ver as transações dos arquitetos registradas pelo canal, para identificar quem está ativo e quem precisa de estímulo.
Job to Be Done — Campanhas Quando quero impulsionar especificações, criar campanhas de bônus visíveis no canal do arquiteto, para aumentar o volume de indicações.

Analisa ROI + Audita ⚙️ Painel admin /dashboard-resultados · /logs
Job to Be Done — Análise Quando avalio o programa, medir ROI e engajamento dos arquitetos pelo painel, para propor ajustes nas regras ao admin.

Fluxo de dados — como o painel recebe as informações do canal

🏪→⚙️ Arquiteto especifica no canal → transação registrada automaticamente no painel
🏪→⚙️ Arquiteto solicita resgate no canal → pedido entra na fila do painel para aprovação
⚙️→🏪 Admin cria campanha no painel → bônus visível no canal do arquiteto
⚙️→🏪 Operador aprova resgate no painel → entrega processada no canal
